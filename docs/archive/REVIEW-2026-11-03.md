# Release cross-check — 3 November 2026

Version: 0.12.3 test candidate. **Not approved for Marketplace publication.**

The review covers the attached Windows lock failure, macOS regressions, recursive
file/folder policy, manual editing, instruction synchronization, persistent locks,
protected child processes, ordinary-user execution, runtime provenance and VSIX
metadata. Passing these checks cannot establish that every OS/provider workflow
is defect-free. The reported Windows build 26300 still needs a device retest.

## Findings corrected

- Windows verification now separates permission preparation from native child
  execution, retains stage/error diagnostics, and retries failed verification.
- Private runtime grants avoid redundant DACL writes while preserving canonical
  handle, junction and hard-link checks. Existing runtime caches are revalidated.
- The private Node pipe patch avoids token-query failure fallback and unbounded
  pipe retries. The rebuilt runtime was downloaded from CI and its artifact,
  binary, archive, source and patch hashes were checked before local packaging.
- A Windows test incorrectly assumed POSIX inherited-pipe behavior. Its fixture
  now exercises a real timeout on both platforms.
- A relative README link broke VSCE packaging for the private-source listing.
  Both platform packages now build without adding inaccessible repository links.
- Deployment instructions now name 0.12.3, avoiding accidental upload of 0.12.2.
- The compatible development-only qs update was applied through npm audit.

## Windows child-stream correction

The native cleanup test exposed a separate compatibility failure: inside LPAC,
Node child creation with `stdio: 'ignore'` fails with `EPERM`. Native captured
pipes and the filesystem-denial probe pass. The job cleanup fixture now uses
pipes so that it can test termination independently; a separate mandatory native
test verifies ignored streams independently of job cleanup.

Programs and CLI libraries can legitimately use ignored streams. Therefore a
passing installation/version smoke is insufficient to approve all real agent
workflows. The correction now passes two read/write null-device handles through
the launcher's explicit inheritance list. The private Node patch uses only those
already-held character-device handles after a native null open fails. Local
malformed-input and handle-type checks pass. CI run 41693923880 subsequently
qualified the new native binary on Windows 2022/2025 with Node 22/24. Original-file and host-service isolation and the
no-administrator requirement are retained. No system-wide device ACL is changed.
Native programs that reopen system devices themselves still require separate
provider-workflow acceptance.

## Dependency audit

The project audit after the qs update reports no high/critical findings and eight
moderate development-tool findings through glob/minimatch, Mocha, VSCE and ESLint.
Do not apply npm's suggested breaking downgrade/forced override to hide them.
These development packages are excluded from the extension payload, but remain
relevant to the trusted build/test environment.

A separate inventory of the bundled npm archive found high-severity undici and
brace-expansion advisories missed by that project audit. Checksum-pinned,
compatible updates to undici 6.29.1, brace-expansion 5.0.12,
postcss-selector-parser 7.1.6 and ip-address 10.7.4 remove the known high/critical
findings in the derived archive. Local npm startup and an offline package install
pass. Two moderate glob/minimatch findings remain visible. CI now repeats this
registry advisory scan and blocks high/critical findings before uploading the
runtime. This is an advisory scan, not an independent security certification.
